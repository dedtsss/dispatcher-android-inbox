## Изменения, подготовленные к первому CI

- Фоновая отправка: ожидание завершения постановки WorkManager, периодический repair без отдельного постоянного процесса, восстановление после отмены, честные lastAttemptAt/syncedAt/ошибка, уведомление о стойких проблемах. Свойства старого кода: исключение enqueue скрывалось, разрыв Room commit→enqueue не имел независимого периодического восстановления. Это гипотеза причин наблюдения, не физическое доказательство конкретного сбоя.
- Запись: foreground-service типа microphone, запущенный из видимой Activity, уведомление Stop→сохранить, partial wake lock только на время записи/локального commit; MediaRecorder/AAC/M4A/параметры качества и принятая история пиков сохранены. Сессия отделена от ViewModel, приватный AtomicFile-журнал сохраняет состав/исходный путь и captureId; повтор после DBcommit возвращает существующее событие. При аварийном останове сырой M4A не удаляется. Жёсткое убийство процесса может оставить незавершённый контейнер: воспроизводимость такого файла не гарантируется, черновик требует проверки, молчаливого успеха нет. [Ограничения Android](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start), [тип microphone](https://developer.android.com/about/versions/14/changes/fgs-types-required).
- Ассистент: после подтверждённого LOCAL commit заметный статус примерно500мс, затем прежнее автозакрытие; успех не означает Drive. Более светлая фиолетовая компактная кнопка, место статуса зарезервировано. Файл доступен при записи; Stop немедленно останавливает микрофон и ждёт завершения импорта перед единым commit. Ошибка импорта оставляет черновик без закрытия. Полноэкранная композиция не переделывается.
- Очередь: плотные раскрываемые элементы, оригинальные суммарные размеры, дата/честный статус/попытки; удаление с явным подтверждением. Настройки Drive компактны, подробности раскрываются. Результат проверки обновления сохраняется с временем; DownloadManager показывает реальные байты/этапы без фиктивного процента, открытие installer не считается установкой.
- Безопасная очистка: keep по умолчанию; только новые события после включения, только syncedAt/полный успех Gateway и checkpoints всех частей; immediate/7дней от подтверждения. Метаданные/размеры сохраняются, неотправленные/ошибочные/частичные и старые записи не очищаются. Отправка/очистка/ручное удаление защищены общим mutex. Room3→4 добавляет nullable диагностику без потери старых полей.
