# Встроенное обновление Catching

Сборка 0.6.4 (10) по умолчанию не содержит адрес канала. В Settings доступна секция «Версия и обновления». Адрес HTTPS-манифеста задаётся Gradle-параметром `-PupdateManifestUrl=https://…`; в CI — переменной репозитория `UPDATE_MANIFEST_URL`. Не помещать PAT, токены или учётные данные в URL и APK.

Существующий CI сохраняет APK в закрытых Actions artifacts. При заданной переменной `UPDATE_APK_URL` он также создаёт `update.json` с реальными параметрами APK и сертификата. Генерация локально:

```bash
python3 scripts/update/generate-manifest.py --apk app-release.apk --apk-url https://example.org/catching.apk --build-tools "$ANDROID_HOME/build-tools/35.0.0" --output update.json
```

Манифест содержит `versionCode`, `versionName`, `apkUrl`, `sha256`, `packageName`, `signerSha256`. В приложении загрузкой управляет Android DownloadManager; идентификатор и метаданные сохраняются для восстановления после перезапуска процесса. Перед открытием штатного установщика проверяются SHA-256 файла, пакет, более высокий versionCode и совпадение текущего сертификата с установленным приложением и манифестом. Ошибка проверки блокирует установку.

Адрес доставки APK должен поддерживать штатную загрузку Android без секретов внутри приложения. Выбор и публикация внешнего канала требуют отдельного решения владельца. Этот код и CI такой канал не создают. Для 0.6.2 встроенная доставка невозможна: в ней ещё нет обновлятора; переход на 0.6.3 выполняется обычной установкой поверх.

Drive OAuth остаётся внешним блокером: на реальном телефоне получен `apiStatus=8 INTERNAL_ERROR`, причина не установлена.
