# Catching — Android Inbox

Catching сохраняет текст, голос M4A/AAC и файлы сначала на телефоне, затем напрямую в обычный видимый каталог **Мой диск / Catching / Inbox**. Для capture не нужны VPS, собственный API, AI или распознавание речи.

## Использование

1. Установите подписанный APK из ручного GitHub Actions. Версия: **0.6.0 (6)**, package `ru.bruce.dispatcherinbox`; постоянная подпись прежняя.
2. В «Настройках» нажмите «Подключить Google Drive», выберите аккаунт и подтвердите доступ. Используется штатный `AuthorizationClient`, единственный scope — `https://www.googleapis.com/auth/drive.file`.
3. «Голос» начинает запись; остановка сохраняет оригинал в очередь. «Текст» раскрывает поле, «Файл» открывает системный выбор. Текст и вложения можно сохранить вместе.
4. Без интернета продолжайте записывать: очередь в Room и копии файлов остаются на телефоне. WorkManager дождётся сети, повторит временные ошибки с backoff. «Очередь» показывает статус и позволяет повторить отправку.

Настройки показывают выбранный аккаунт и состояние доступа. Если Google требует подтверждения, нажмите «Подключить повторно». Access token получается заново штатным SDK, не сохраняется в DataStore и не выводится в журнал. URL и Bearer token собственного сервера больше не используются. Debug-сборка также не имитирует успешную отправку.

Системные входы сохранены: `ACTION_SEND`, `ACTION_SEND_MULTIPLE`, `ACTION_ASSIST` / `ROLE_ASSISTANT`, Quick Settings tile и launcher shortcut. Assistant открывает компактную панель с главным голосовым действием. В настройках можно запросить роль ассистента и добавить плитку в шторку; доступность зависит от Android и прошивки.

## Формат сырого Inbox

Время в именах — UTC с миллисекундами; полный локальный UUID обеспечивает уникальность и связь с Room.

```text
Catching/Inbox/
  2026-11-02_052501_123_<UUID>_voice-....m4a
  2026-11-02_052724_456_<UUID>_note.txt
  2026-11-02_053003_789_<UUID>/
    001_note.txt
    002_document.pdf
    003_photo.jpg
```

Один оригинал — один файл; несколько связанных оригиналов — одна папка события. Текст сохраняется UTF-8 без обрезки пробелов и переводов строк. Вложения загружаются без преобразования, потоково через resumable upload. При обрыве незавершённая передача начинается заново с тем же зарезервированным Drive ID; частичная сессия не используется как доказательство сохранения.

Перед созданием каждого объекта его Drive ID записывается в Room. После потери ответа или перезапуска приложение проверяет этот ID, размер и MD5 удалённого оригинала. Только подтверждение всех частей позволяет выставить `synced`. Несовпадение содержимого или корзина дают ошибку, без перезаписи оригинала. Данные локально автоматически не удаляются; ручное удаление из очереди удаляет локальные копии и не удаляет уже загруженные объекты Drive.

`drive.file` видит файлы, созданные/разрешённые этому приложению. Catching находит доступные ему каталоги `Catching/Inbox`, иначе создаёт их. Одноимённая папка, созданная вручную и не предоставленная приложению, может оставаться недоступной при этом минимальном scope. `appDataFolder` не используется.

## Проверка и APK

Тяжёлые сборки выполняются в GitHub Actions, workflow `.github/workflows/android.yml`, только `workflow_dispatch`. В нём:

- `testReleaseUnitTest`, `lintRelease`, `assembleRelease` и APK инструментальных тестов;
- постоянный ключ из существующих `DISPATCHER_SIGNING_*` Secrets; отсутствие ключа завершает сборку ошибкой;
- артефакт `catching-0.6.0-release`: устанавливаемый release APK, `SHA256SUMS`, сертификат и `oauth-registration.txt`;
- Android 35 emulator: capture без сети (текст, реальный MediaRecorder, исходные байты файла), Share/SEND_MULTIPLE, ACTION_ASSIST, восстановление Room и снимки экранов;
- отдельные артефакты результатов тестов и доказательств на Android. Срок хранения основных артефактов — 3 дня по текущему регламенту экономии квоты.

Установка поверх прежней версии:

```bash
adb install -r catching-0.6.0-release.apk
```

Пакет, постоянный ключ и данные приложения сохраняются. Room v1 → v2 добавляет только таблицу Drive ID, без destructive migration. Старые записи `synced` не загружаются повторно; сохранённые локально `queued`/`error` отправляются в Drive. Если старый режим ранее уже удалил оригинал, приложение сообщает об отсутствующем файле, не имитируя успех.

## Одноразовая настройка Google OAuth

В Google Cloud проекте должны быть включены **Google Drive API**, экран согласия и **OAuth client типа Android**:

- package: `ru.bruce.dispatcherinbox`;
- SHA-1: точный `Signer #1 certificate SHA-1 digest` из `oauth-registration.txt` подписанного release APK;
- scope: `https://www.googleapis.com/auth/drive.file`;
- для приложения в статусе Testing аккаунт владельца должен входить в список тестовых пользователей.

SHA-1 нельзя подменять отпечатком временного debug-ключа. Android client secret, web client, backend redirect URI и VPS OAuth-прокси для этого потока не нужны. Регистрацию и согласие владельца нельзя подтвердить unit-тестами: после настройки на телефоне нужно подключить аккаунт, отправить тестовый текст и файл, проверить их байты в `Catching/Inbox`. Точные результаты текущего исполнения — в [отчёте](docs/issue-7-report.md).

## Границы

Агентная обработка, ChatGPT, Obsidian, виджет, STT и автоматическая очистка оригиналов относятся к отдельным этапам. Android может откладывать фоновые задачи из-за Doze и ограничений производителя. Проверка на эмуляторе не заменяет проверку выбора роли и жеста assistant на целевом HyperOS-устройстве.
